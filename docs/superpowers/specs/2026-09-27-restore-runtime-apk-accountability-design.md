## Package and license accountability

The original design's RPM-only clauses apply to the rejected UBI candidates. For this APK candidate, the immutable base must retain its original APK installed database and OS identity. The probe records the APK database path and SHA-256, parses installed package name/version/license and owned files from that database with strict bounds, and compares the complete package name/version set to Syft's `apk` catalog from the same extracted amd64 base. Empty, malformed, duplicate, mismatched, hidden, or unowned package records fail even when Grype reports zero findings. Loader and every required base ELF library must be owned by one of those installed packages. The exact-image inventory may include a final symlink directly owned by an installed APK package when its resolved target is a directory contained in the extracted root; this does not transfer ownership to target bytes. Canonical ELF bytes must still resolve within the root and be directly owned as regular files by an installed package. No path outside that root is accepted. In the unexecuted rootfs, the exact `/etc/mtab -> /proc/mounts` dangling pseudo-filesystem link may be recorded as metadata only; it is never an ELF owner and grants no target ownership. The dossier identifies package-manager type `apk` explicitly and uses a new schema version rather than mislabeling APK data as `rpmdb`.

The seven APK `L:` declarations are license identifiers, not the corresponding license texts or a legal clearance. For this candidate only, replace the original probe's `baseLicenses` file-array requirement with a complete, hashed APK package/license declaration inventory; retain the original UBI file-based license fixtures as historical RPM evidence. A missing or ambiguous APK declaration rejects the preflight. The technical preflight and local image build may report `license-review-pending`, but that state must never authorize publication. The supplemental runtime sidecar binds that state to exact source SHA, base/donor manifest, final image ID and SBOM hash; `image-release.mjs publish` and relocated `validate` reject absent, pending, stale, or mismatched license review before any registry effect or release output. Only an independently reviewed, committed package-source/license-text and notice/source-offer record for the exact bound packages can advance the sidecar to an approved state. The agent must not self-approve legal obligations or synthesize a passing review record. Preserve the donor's hashed Cockroach license/notice inventory. Do not claim that a zero-match scan or package metadata alone fulfills legal obligations, and do not copy donor OS libraries or an unowned CA bundle to fill a gap.

## Probe and final-image gates

Change only the read-only x86_64 candidate probe first. Preserve immutable index and amd64-child verification, digest-only Skopeo fetch, donor ELF/native-file and license inspection, base-owned CA trust, source-SHA binding, sanitized failure artifacts, and unchanged `grype --fail-on high`. Negative tests cover absent APK DB, malformed/duplicate package records, absent loader/libc owner, missing license declarations, Syft/APK mismatch, empty catalog, high finding, and symlink escape. The CI workflow accepts no secret and cannot publish or deploy. An APK candidate is only eligible for assembly if this exact-source Linux preflight produces a complete candidate dossier with zero High/Critical matches and no missing native dependency.

Before implementation, a supplemental execution plan must supersede the original plan's RPM-only Task 1 dossier/negative tests and RPM-only stop condition for this exact APK candidate; the UBI outcomes remain historical evidence, not tests to delete. If preflight passes, adapt the original plan's Tasks 2–4 to preserve the APK database, verify the same package/ownership/license evidence in the imported final image, and run the existing numeric non-root, read-only `/tmp`, secure Cockroach TLS/SQL positive and negative proofs. Keep `api`, `worker`, `maintenance`, `web`, and `restore-tools` as five separate Nix-sourced images; preserve COPY-only Docker packaging, generated artifact drift, portable release receipts, immutable digests, SBOM/Grype scans of exact image IDs, and no registry output before all five pass. A preflight pass is not final-image acceptance. GHCR publication, production reconcile, credentials, B2 configuration and restore remain outside this approval.

If this APK candidate fails any gate, record the exact digest, phase, scanner database, package/CVE/fix-state or missing dependency, leave M4 blocked, and choose a different supported candidate only through another reviewed decision. No scanner threshold reduction, metadata deletion, fabricated owner, or production fallback is allowed.
